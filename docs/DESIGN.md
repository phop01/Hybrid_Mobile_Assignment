# KKUNK Today: เหตุผลของการออกแบบ

เอกสารนี้อธิบายว่าแต่ละฟีเจอร์และฟังก์ชัน "มีไว้ทำไม" ใช้ตอบคำถามตอนนำเสนอได้
ครึ่งแรกคือส่วนที่เพิ่มใน KKUNK Today (แจ้งซ่อม ประกาศ กล่องแจ้งเตือน) ครึ่งหลังคือส่วนกิจกรรม/เช็กอินที่ต่อยอดมาตลอดเทอม

## ปัญหาและผู้ใช้

- **ผู้ใช้:** นักศึกษาและเจ้าหน้าที่ มหาวิทยาลัยขอนแก่น วิทยาเขตหนองคาย
- **ปัญหา:** เรื่องในมอกระจายอยู่ในกลุ่ม LINE, เพจ, บอร์ดหน้าตึก · แจ้งซ่อมแล้วไม่รู้ว่าใครรับเรื่อง · เรื่องเดียวกันแจ้งซ้ำหลายคน · ชั่วโมงกิจกรรม/จิตอาสาต้องจดเอง
- **หลักคิด:** ทุกเรื่องต้อง **มีคนรับผิดชอบ** และ **ติดตามสถานะได้** และอีกฝั่งต้องรู้ทันทีเมื่อมีความคืบหน้า (แจ้งเตือนเป็นหัวใจ ไม่ใช่ของแถม)

## เรื่องแจ้งซ่อม (`Ticket` ใน `src/types/models.ts`)

```
open (มีคนแจ้ง) → accepted (เจ้าหน้าที่อาคารรับเรื่อง) → done (ทำเสร็จ) → confirmed (ผู้แจ้งยืนยัน)
                     ↑________ reopen (ยังไม่เรียบร้อย) ________|
แตกออกได้: rejected (เจ้าหน้าที่ปฏิเสธ + เหตุผล) · cancelled (ผู้แจ้งยกเลิก) · release (ผู้รับคืนเรื่อง → open)
```

| ตัดสินใจ | เหตุผล |
|---|---|
| เอาเรื่อง "ขอความช่วยเหลือ" และชั่วโมงช่วยเพื่อนออก (30 ก.ย.) | ชั่วโมงควรมาจากกิจกรรมที่มหาวิทยาลัยรับรอง (เข้าร่วมกิจกรรม / กิจกรรมจิตอาสา) ไม่ใช่นักศึกษายืนยันให้กันเอง · แอปโฟกัสงานที่มีผู้รับผิดชอบชัด |

| เจ้าหน้าที่แยกหน่วยงาน: งานกิจกรรม (สร้างกิจกรรม/ตรวจหลักฐาน) · อาคารสถานที่ (รับงานซ่อม) server ตรวจด้วย `requireStaff` | ตรงกับการทำงานจริง แต่ละคนเห็นเฉพาะเมนูและแจ้งเตือนของงานตัวเอง ทำนอกหน้าที่ไม่ได้แม้ยิง API ตรง |
| แจ้งซ่อม: เจ้าหน้าที่อาคารรับเท่านั้น | ช่างอาคารมีเครื่องมือและหน้าที่ · คนอื่นกด "เจอเหมือนกัน" เพื่อติดตามแทน |
| รับเรื่องได้คนเดียว คนที่สองได้ 409 | กันสองคนไปจุดเดียวกัน · แอปโหลดสถานะใหม่ทันทีเมื่อเจอ 409 |
| แจ้งซ่อมต้องมีรูป · รูปหลังซ่อมไม่บังคับ | ช่างรู้ว่าต้องเตรียมอะไรไป · บางจุดถ่ายรูปหลังซ่อมยากหรือเครื่องเจ้าหน้าที่ไม่มีกล้อง จึงไม่บังคับ แต่ผู้แจ้งยังเป็นคนยืนยัน (กด "ยังไม่เรียบร้อย" ได้) งานจึงไม่ปิดลอย ๆ |
| ผู้แจ้งเป็นคนยืนยัน (หรือกด "ยังไม่เรียบร้อย" พร้อมเหตุผล) | คนที่เจอปัญหาคือคนที่รู้ว่าแก้แล้วจริงไหม |
| กันแจ้งซ้ำ: เรื่องหมวดเดียวกันที่ยังไม่ปิดในรัศมี 50 ม. → เสนอ "เจอเหมือนกัน" | เจ้าหน้าที่ไม่ต้องไล่รวมเรื่องซ้ำ และเห็นว่าเรื่องไหนกระทบหลายคน · คนกดได้แจ้งเตือนความคืบหน้าเหมือนผู้แจ้ง |
| คิวงานเจ้าหน้าที่เรียงตาม: คนเจอเหมือนกัน ×3 + ชั่วโมงที่รอ ÷6 (สูงสุด 72 ชม.) + หมวดไฟฟ้า/ทางเดิน +4 | ความปลอดภัยมาก่อน เรื่องที่กระทบหลายคนมาก่อน และเรื่องเก่าไม่ถูกลืม (`urgencyScore` ใน `lib/tickets.ts`) |
| เจ้าหน้าที่นัดเวลาจากปุ่มวัน + เวลา (ไม่พิมพ์) | เร็วกว่า กรอกผิดรูปแบบไม่ได้ เวลาที่ผ่านไปแล้วกดไม่ได้ |
| ปิดงานไกลจุดแจ้งเกิน 200 ม. → เตือนแต่ไม่บล็อก | ช่างอาจกดตอนกลับถึงห้องช่าง การบล็อกทำให้ใช้งานจริงไม่ได้ แต่เตือนให้ตรวจรูปอีกครั้ง |
| ฟอร์ม 3 ขั้น (เรื่องอะไร → ที่ไหน → รายละเอียด) ด้วย `useReducer` | แต่ละขั้นมีคำถามเดียว มือถือจอเล็กไม่ต้องเลื่อนยาว · ไปขั้นถัดไปได้เมื่อขั้นนี้ถูกต้อง · เข้าขั้น 2 แล้วหาตำแหน่งให้อัตโนมัติ |
| ส่งตอนไม่มีเน็ต → เก็บในคิว SQLite พร้อม Idempotency-Key ส่งเองเมื่อมีเน็ต | ในตึก/ห้องน้ำสัญญาณมักไม่ดี · ส่งซ้ำด้วย key เดิม server คืนเรื่องเดิม ไม่สร้างซ้ำ |

## นำทาง (`src/components/navigate-buttons.tsx`, `src/app/directions.tsx`)

ปุ่มหลัก **"นำทางด้วยแผนที่"** เปิดแอปแผนที่ของเครื่อง (`mapsUrl`: iPhone = Apple Maps, Android/เว็บ = Google Maps โหมดเดิน) เพราะนำทางเลี้ยวซ้ายขวาได้ดีกว่า (ผู้ใช้ทดสอบแล้วเลือกแบบนี้ 30 ก.ย.) · ปุ่มรอง "ดูระยะทางในแอป" คือหน้าด้านล่าง

### หน้าระยะทางในแอป

| ตัดสินใจ | เหตุผล |
|---|---|
| หน้าเส้นทางในแอป แทนการกระโดดไป Apple/Google Maps | ไม่ต้องสลับแอป ดูระยะแล้วกลับมากดรับเรื่อง/เช็กอินต่อได้ทันที (เพื่อน 9 คน: 2 คนเปิดแอปภายนอก, 7 คนไม่มีนำทาง, ไม่มีใครบอกระยะ) |
| เส้นตรง + ระยะ + เวลาเดิน (80 ม./นาที) คำนวณในเครื่อง ไม่ใช้บริการ routing | ในวิทยาเขตส่วนใหญ่เดินไป เส้นตรงพอ · ฟรี ไม่มี API key · ไม่พังเมื่อเน็ตห้องสอบไม่ดี (Google Directions ต้องผูกบัตร, OSRM demo ไม่รับประกัน) |
| ติดตามตำแหน่งเฉพาะตอนเปิดหน้านี้ (`watchPositionAsync` ทุก 5 ม.) ออกจากหน้าแล้วหยุด | ระยะลดลงตามที่เดิน โดยไม่ติดตามเบื้องหลัง · ≤ 30 ม. ขึ้น "ถึงแล้ว" (เผื่อ GPS คลาดเคลื่อน) |
| ซูมให้เห็นทั้งสองจุดแค่ครั้งแรก | หลังจากนั้นไม่ขยับกล้องเอง ไม่แย่งนิ้วผู้ใช้ที่กำลังเลื่อนแผนที่ |
| ไม่ให้สิทธิ์ตำแหน่ง → ยังเห็นหมุดเป้าหมาย + ปุ่มเปิดการตั้งค่า | ฟีเจอร์หลักยังใช้ได้ ไม่ทำให้หน้าว่าง |
| พิกัดมาทาง route params ตรวจด้วย `parseCoordinates` ก่อนใช้ | ลิงก์มาจากภายนอกได้ ค่าผิดแสดงหน้า "ไม่พบตำแหน่ง" |
| ยังมีปุ่มรอง "เปิดในแอปแผนที่" | สำหรับที่ไกลนอกวิทยาเขตที่ต้องการนำทางเลี้ยวซ้ายขวา |
| เว็บใช้ `navigator.geolocation` ตรง ๆ | `watchPositionAsync` ของ expo-location บนเว็บจับคู่ event ด้วย id ของเบราว์เซอร์ อาจไม่ตรงแล้วอัปเดตหายเงียบ ๆ |

## กล่องแจ้งเตือน (`src/state/inbox-context.tsx`, `server/tickets.mjs`)

| ตัดสินใจ | เหตุผล |
|---|---|
| **server เป็นคนตัดสินว่าใครควรรู้อะไร** แล้วใส่กล่องของคนนั้น (`notify()`) | กติกาอยู่ที่เดียว เช่น "เรื่องซ่อมใหม่แจ้งเฉพาะเจ้าหน้าที่อาคาร" แอปไม่ต้องรู้ข้อมูลคนอื่น |
| แอป poll `GET /me/inbox?since=` ทุก 8 วิ ขณะเปิดอยู่ แล้วเด้งแจ้งเตือนในเครื่อง | ใช้ได้ใน Expo Go ไม่ต้องมีบัญชี push/Firebase · ถี่พอให้ "อีกฝั่งกด → เครื่องนี้เด้ง" ภายในไม่กี่วินาที |
| ครั้งแรกหลัง login ดึงของเก่ามาแสดงในกล่องแต่ไม่เด้งย้อนหลัง | ไม่ให้เด้งทีละ 10 อันตอนเปิดแอป |
| payload เก็บแค่ประเภท + ID (`targetFor` ตรวจรูปแบบ ID ก่อนใช้) | ไม่มีข้อมูลส่วนตัวในแจ้งเตือน · หน้าปลายทางโหลดข้อมูลล่าสุดเอง · ID ผิด/ถูกลบ → หน้า "ไม่พบเรื่องนี้" |
| เตือนก่อนนัดซ่อม 1 ชม. ตั้งเป็น local scheduled notification จากเวลาในข้อมูล | ใช้ได้แม้ปิดแอป · เวลานัดเปลี่ยน → ตั้งใหม่ · เรื่องปิด → ยกเลิก · logout → ยกเลิกทั้งหมด |
| มีแท็บ "แจ้งเตือน" พร้อมตัวเลขยังไม่อ่าน | แจ้งเตือนของระบบหายเมื่อปัดทิ้ง ต้องย้อนดูได้ · screen reader อ่านจำนวนจากป้ายแท็บ |
| บนเว็บแสดงเป็นแถบด้านบนของแอป + แจ้งเตือนของเบราว์เซอร์ (Notification API ถ้าผู้ใช้กดเปิดในแท็บแจ้งเตือน) และ poll ต่อแม้แท็บอยู่เบื้องหลัง | เว็บไม่มีแจ้งเตือนของระบบ · เจ้าหน้าที่ใช้บนเว็บคู่กับนักศึกษาบนมือถือได้ |
| ประกาศจากเจ้าหน้าที่ส่งถึงทุกคน + ค้างบนหน้า "วันนี้" จนหมดเวลาที่ตั้ง (1–72 ชม.) | เรื่องอย่างปิดน้ำกระทบทุกคน · หมดเวลาแล้วหายเอง ไม่รกหน้าแรก |

# ส่วนกิจกรรมและเช็กอิน (ต่อยอดจากงานตลอดเทอม)

## ปัญหาของส่วนกิจกรรม

- **ผู้ใช้:** นักศึกษาที่ต้องเข้าร่วมกิจกรรมให้ครบตามที่มหาวิทยาลัยกำหนด (ข้อมูลตัวอย่างใช้พิกัดมหาวิทยาลัยขอนแก่น วิทยาเขตหนองคาย)
- **ปัญหา:** ไม่รู้ว่ามีกิจกรรมอะไร ลืมวันงาน การเช็กชื่อกระดาษเซ็นแทนกันได้ และนักศึกษาไม่มีหลักฐานในมือถ้าชื่อตกหล่น
- **เส้นทางหลัก:** ค้นหา → บันทึกไว้ / ลงทะเบียน → แจ้งเตือนเมื่อเปิดเช็กอิน → ไปถึงงาน → ตรวจตำแหน่ง + ถ่ายรูป → จำนวนกิจกรรมเพิ่ม

## ข้อมูลหลัก (`src/types/models.ts`)

| ข้อมูล | เหตุผล |
|---|---|
| `Activity.location.radiusM` | แต่ละสถานที่ใหญ่ไม่เท่ากัน (ห้องประชุม 120 ม. / แปลงป่า 300 ม.) รัศมีเช็กอินจึงต้องกำหนดรายกิจกรรม |
| `Activity.checkInMethod: 'app' \| 'paper'` | หลายกิจกรรมยังใช้ใบเซ็นชื่อ แอปต้องรองรับทั้งสองแบบ |

| ตรวจหลักฐาน: ผ่าน / ไม่ผ่าน + เหตุผล (มีเหตุผลสำเร็จรูปให้เลือก) | แทน "ผู้จัดจำลอง" ของ Assignment 11 ไม่ผ่านแล้วนักศึกษารู้ว่าต้องแก้อะไร และส่งใหม่ได้ |
| server ตอบ 409 ถ้ารายการไม่ได้รอตรวจแล้ว | กันผู้จัด 2 คนตรวจรายการเดียวกันซ้ำ |

## Final · ชั่วโมงกิจกรรม (`src/lib/attendance.ts`, หน้าโปรไฟล์)

| ฟีเจอร์ | เหตุผล |
|---|---|
| `Activity.hours` = ระยะเวลางาน ปัดครึ่งชั่วโมง (server คำนวณ) | มหาวิทยาลัยนับเป็นชั่วโมงกิจกรรม ไม่ใช่จำนวนครั้ง และ client แก้ค่าไม่ได้ |
| นับเฉพาะ `checked_in` / แสดงชั่วโมงที่รอตรวจแยก | ลงทะเบียนแล้วไม่ไป หรือหลักฐานยังไม่ผ่าน ต้องไม่ถูกนับ แต่ผู้ใช้ควรรู้ว่ามีรออยู่ |
| แถบความคืบหน้าเทียบเป้าหมาย `REQUIRED_HOURS` + แยกตามประเภท | รู้ว่าขาดอีกกี่ชั่วโมง และขาดประเภทไหน |
| ประวัติกิจกรรมที่ได้ชั่วโมง | ใช้เป็นหลักฐาน/พอร์ต แตะแล้วเปิดรายละเอียดและรูปหลักฐาน |
| แจ้งเตือนผลตรวจ (ผ่าน/ไม่ผ่านพร้อมเหตุผล) | นักศึกษารู้ทันทีว่าได้ชั่วโมงแล้ว หรือต้องส่งหลักฐานใหม่ |
| ผู้จัดส่งประกาศถึงผู้ลงทะเบียน (ข้อความสำเร็จรูป 3 แบบ หรือพิมพ์เอง) แอปดึงทุก 15 วิแล้วเด้งแจ้งเตือนในเครื่อง | เรื่องด่วน (เปิดเช็กอิน ย้ายห้อง เลื่อนเวลา) ต้องมาจากผู้จัดจริง ไม่ต้องมี push server/บัญชี Firebase จึงรันฟรีบน Expo Go |
| นักศึกษาเลือกเวลาเตือนเอง (1 วัน / 1 ชม. / ตอนเปิดเช็กอิน) ซ่อนตัวเลือกที่เลยเวลา | แต่ละคนเดินทางไกลใกล้ไม่เท่ากัน แทนปุ่มทดสอบ 10 วิที่ใช้จริงไม่ได้ |
| ขอสิทธิ์แจ้งเตือนหลังลงทะเบียนสำเร็จ | ผู้ใช้เข้าใจเหตุผลทันที (จะได้รับประกาศของกิจกรรมนี้) ไม่ขอตอนเปิดแอป |

## Final · สมัครสมาชิกและความปลอดภัย

| ฟีเจอร์ | เหตุผล |
|---|---|
| สมัครสมาชิก → server ส่ง token กลับเลย | ผู้ใช้ไม่ต้อง login ซ้ำหลังสมัคร |
| รหัสผ่านเก็บเป็น scrypt hash, รหัสผ่านอย่างน้อย 8 ตัว | ข้อมูลรั่วก็ไม่ได้รหัสผ่านจริง |
| ใส่รหัสผิด 5 ครั้ง ล็อก 60 วินาที (429) | กันการเดารหัสผ่านแบบอัตโนมัติ |
| `safeNext` ไม่รับ path ที่ขึ้นต้นด้วย `//` | กันลิงก์ login พาออกไปเว็บภายนอก (open redirect) |
